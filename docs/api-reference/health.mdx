Health API JacRed предоставляет диагностические эндпоинты для проверки состояния сервиса, версии сборки, активных фоновых задач и подтверждения корректно настроенного `apikey`. Все эндпоинты работают без авторизации (кроме проверки apikey), удобны для health-check в Docker, Kubernetes или мониторинга.

## Проверка статуса

```text
GET /health
```

Возвращает `200 OK` с JSON-объектом:

```json
{ "status": "OK" }
```

```bash
curl "http://localhost:9117/health"
```

Используйте в Docker healthcheck или для liveness-проб.

## Версия сборки

```text
GET /version
```

Возвращает информацию о версии, git-коммите и дате сборки:

```json
{
  "version": "3.9.3",
  "gitSha": "c704d032",
  "gitBranch": "main",
  "buildDate": "YYYY-MM-DD HH:mm:ss UTC"
}
```

```bash
curl "http://localhost:9117/version"
```

## Время последнего обновления БД

```text
GET /lastupdatedb
```

Возвращает дату и время самой свежей записи в `masterDb`:

```json
{ "lastupdatedb": "15.01.2025 12:34" }
```

```bash
curl "http://localhost:9117/lastupdatedb"
```

## Проверка apikey и совместимости

```text
GET /api/v1.0/conf?apikey=YOUR_KEY
```

Проверяет, что переданный apikey соответствует настройке `apikey` в конфиге. Полезно для интеграций (Lampa и другие клиенты используют этот эндпоинт при первом подключении).

<ParamField path="query.apikey" type="string">
  Проверяемый ключ. Можно передать через параметр или заголовок `X-Api-Key`.
</ParamField>

Ответ:

```json
{
  "jacred": true,
  "configured": true,
  "apikey": true,
  "version": "3.9.3"
}
```

Поля:

| Поле | Значение |
| --- | --- |
| `jacred` | Всегда `true`, маркер сервиса JacRed |
| `configured` | `true`, если в конфиге задан `apikey` |
| `apikey` | `true`, если переданный ключ совпадает с настройкой (или `apikey` не сконфигурирован) |
| `version` | Версия JacRed |

## Активные фоновые задачи

```text
GET /health/background-jobs
```

Возвращает список активных `ParseAllTask` и `UpdateTasksParse` задач. Используйте для проверки, что парсер не завис.

`pagesCompleted` и `pagesTotal` — это страницы листинга текущего цикла ParseAll, не раздачи. `currentCategory` — id или slug раздела, `currentPage` — номер страницы в этом разделе, а не дробь «текущее/всего».

<ResponseField name="id" type="string">
  Внутренний идентификатор `{tracker}:{job}`, например `anibelka:ParseAllTask`.
</ResponseField>

<ResponseField name="tracker" type="string">
  Slug трекера.
</ResponseField>

<ResponseField name="job" type="string">
  Cron-действие: `ParseAllTask` или `UpdateTasksParse`.
</ResponseField>

<ResponseField name="startedAtUtc" type="string">
  Время старта в UTC (ISO-8601).
</ResponseField>

<ResponseField name="elapsedSeconds" type="integer">
  Сколько секунд задача уже выполняется.
</ResponseField>

<ResponseField name="pagesCompleted" type="integer">
  Сколько страниц листинга уже обработано в этом цикле.
</ResponseField>

<ResponseField name="pagesTotal" type="integer">
  Сколько страниц стояло в очереди на старте этого цикла. У `UpdateTasksParse` обычно `0`.
</ResponseField>

<ResponseField name="percent" type="integer">
  Округлённый процент `pagesCompleted/pagesTotal`. `null`, если `pagesTotal` равен 0.
</ResponseField>

<ResponseField name="currentCategory" type="string">
  Раздел, который парсится сейчас (`32`, `serial-hd`). Не путайте с прогрессом.
</ResponseField>

<ResponseField name="currentPage" type="integer">
  Номер страницы листинга в `currentCategory`.
</ResponseField>

<ResponseField name="summary" type="string">
  Строка для `curl`: `6/154 pages · category 32 · page 5`. Без прогресса — `running`.
</ResponseField>

```json
{
  "jobs": [
    {
      "id": "anibelka:ParseAllTask",
      "tracker": "anibelka",
      "job": "ParseAllTask",
      "startedAtUtc": "2026-09-08T13:48:01.5624351Z",
      "elapsedSeconds": 940,
      "pagesCompleted": 6,
      "pagesTotal": 154,
      "percent": 4,
      "currentCategory": "32",
      "currentPage": 5,
      "summary": "6/154 pages · category 32 · page 5"
    }
  ]
}
```

```bash
curl "http://localhost:9117/health/background-jobs"
```

<Note>
  Короткие синхронные запуски `parse` могут завершиться до проверки и не попасть в список. Отслеживайте их через `Data/log/{tracker}.log`.
</Note>

## Пример healthcheck для Docker

```yaml
services:
  jacred:
    image: ghcr.io/jacred-fdb/jacred:latest
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9117/health"]
      interval: 30s
      timeout: 5s
      retries: 3
```
