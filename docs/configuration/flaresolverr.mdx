Rutracker и Kinozal защищены Cloudflare. Прямой `HttpClient` не может обойти `cf_clearance` cookie (отличается TLS fingerprint). FlareSolverr запускает реальный браузер Chromium, **решает** challenge и отдаёт cookie. Дальше страницы забирает **cffetch** — HTTP с отпечатком Chrome (`curl_cffi`) на `:8192` (`ghcr.io/jacred-fdb/cffetch`, host network рядом с FlareSolverr).

Замер на master 10.09.2026: listing/hash ~**0.18 с** против **0.5–1.2 с** у `request.get` (page.goto). Тот же urllib с cookie даёт `403` + `cf-mitigated`. SOCKS cffetch должен совпадать с `PROXY_URL` FlareSolverr (WARP).

У каждого guarded-хоста **своя** сессия FlareSolverr (`jacred-kinozal_guru`, `jacred-rutracker_org`, …). Cron `/cron/cloudflare/Warmup` прогревает сессию и наполняет jar для быстрого пути.

## Принцип работы

1. JacRed просит FlareSolverr (`request.get`) решить Cloudflare, если jar ещё нет.
2. Из `solution` забираются cookie и User-Agent; cffetch проверяет их делом.
3. Следующие GET идут в `POST http://127.0.0.1:8192/fetch` с TLS Chrome.
4. `cf-mitigated` или страница «Just a moment…» — браузер снова, jar обновляется. Голый 403 трекера cookie не сбрасывает.

Без запущенного cffetch JacRed остаётся на браузере (как раньше).

## Конфигурация

```yaml
flaresolverr:
  enable: true
  url: http://127.0.0.1:8191/v1   # compose (JacRed на bridge): http://host.docker.internal:8191/v1
  maxTimeoutMs: 300000             # 5 минут на решение challenge
  sessionIdleMinutes: 120          # держать сессию Chromium живой
  browserTimeoutRetries: 1         # повторить в той же сессии
  recycleAfterTimeouts: 3          # пересоздать сессию после N таймаутов подряд
  guardedHours: 6
  recheckMinutes: 30

cffetch:
  enable: true
  url: http://127.0.0.1:8192/fetch # compose (JacRed на bridge): http://host.docker.internal:8192/fetch
  impersonate: chrome136           # не старше Chromium FlareSolverr (на master — 148)
  timeoutSeconds: 25
  maxConcurrent: 4                 # иначе 429 трекера
  clearanceMinutes: 60
  proxy: socks5://127.0.0.1:20001  # тот же SOCKS, что PROXY_URL у FlareSolverr
```

<ParamField path="enable" type="boolean">
  Включить FlareSolverr. При `false` JacRed попытается использовать `Rutracker.alias`.
</ParamField>

<ParamField path="url" type="string">
  URL FlareSolverr API. По умолчанию `http://127.0.0.1:8191/v1`. JacRed в compose на bridge при host-network FlareSolverr: `http://host.docker.internal:8191/v1`.
</ParamField>

<ParamField path="maxTimeoutMs" type="number">
  Максимальный таймаут ожидания ответа FlareSolverr в миллисекундах. Рекомендуется 300000 (5 минут).
</ParamField>

<ParamField path="sessionIdleMinutes" type="number">
  Время неактивности сессии Chromium перед удалением. Держите 120+ чтобы минимизировать пересоздания.
</ParamField>

<ParamField path="recycleAfterTimeouts" type="number">
  Пересоздать сессию только после N последовательных таймаутов браузера. Значение 3 защищает от лишних пересозданий.
</ParamField>

<ParamField path="cffetch.enable" type="boolean">
  Быстрый путь после solve. При `false` или если cffetch на `:8192` не запущен, все GET идут через браузер.
</ParamField>

<ParamField path="cffetch.proxy" type="string">
  SOCKS5 тот же, что `PROXY_URL` у FlareSolverr. Без совпадения IP cookie не проходит.
</ParamField>

## Docker Compose: cffetch + FlareSolverr

Образ `ghcr.io/jacred-fdb/cffetch` (amd64, arm64). Host network, как у FlareSolverr: тот же WARP SOCKS и тот же выходной IP. Не публикуйте `:8192` наружу.

```yaml
services:
  jacred:
    image: ghcr.io/jacred-fdb/jacred:latest
    extra_hosts:
      - "host.docker.internal:host-gateway"
    depends_on:
      - flaresolverr
      - cffetch

  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    restart: unless-stopped
    network_mode: host
    environment:
      - TZ=Europe/Moscow
      - LOG_LEVEL=info
      - PROXY_URL=socks5://127.0.0.1:20001
      - DISABLE_MEDIA=true

  cffetch:
    image: ghcr.io/jacred-fdb/cffetch:latest
    container_name: cffetch
    restart: unless-stopped
    network_mode: host
    environment:
      - CFFETCH_PROXY=socks5://127.0.0.1:20001
      - CFFETCH_IMPERSONATE=chrome136
```

В `init.yaml` (JacRed на bridge, cffetch/FlareSolverr на host network):

```yaml
flaresolverr:
  enable: true
  url: http://host.docker.internal:8191/v1

cffetch:
  enable: true
  url: http://host.docker.internal:8192/fetch
  proxy: socks5://127.0.0.1:20001
```

Host-run JacRed оставляет `http://127.0.0.1:8191/v1` и `http://127.0.0.1:8192/fetch`. `http://flaresolverr:8191/v1` работает только если FlareSolverr в той же compose-сети (без `network_mode: host`).

Проверка: `curl -sS http://127.0.0.1:8192/health`. Alpine-образ JacRed python не содержит — cffetch отдельный контейнер.

После первого push пакет `ghcr.io/jacred-fdb/cffetch` в GitHub Packages может быть private; выставьте visibility public, как у `jacred`.

## Fallback: venv на хосте

```bash
python3 -m venv /opt/jacred/venv-cffetch
/opt/jacred/venv-cffetch/bin/pip install 'curl_cffi>=0.7,<1.0'

  /opt/jacred/venv-cffetch/bin/python /opt/jacred/tools/cffetch/app.py
```

## VPS с датацентровым IP: WARP

На VPS без residential/ISP IP Cloudflare блокирует FlareSolverr. Решение: добавить WARP как SOCKS5-прокси для FlareSolverr.

```yaml
services:
  warp:
    image: caomingjun/warp
    container_name: warp
    restart: unless-stopped
    cap_add:
      - NET_ADMIN
    volumes:
      - warp-data:/var/lib/cloudflare-warp

  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    network_mode: host
    environment:
      - PROXY_URL=socks5://127.0.0.1:20001
      - DISABLE_MEDIA=true

  cffetch:
    image: ghcr.io/jacred-fdb/cffetch:latest
    network_mode: host
    environment:
      - CFFETCH_PROXY=socks5://127.0.0.1:20001
      - CFFETCH_IMPERSONATE=chrome136

volumes:
  warp-data:
```

<Note>
  Том `warp-data` сохраняет регистрацию WARP между перезапусками. Без него каждый перезапуск создаёт новый WARP-идентификатор, что может вызвать повторные Cloudflare challenges.
</Note>

## Cron-прогрев сессии

Для предотвращения закрытия сессии Chromium добавьте в `Data/crontab`:

```crontab
# Прогрев каждые 20 минут
5,25,45 * * * *  /opt/jacred/Data/run-job.sh cloudflare-keepalive http://127.0.0.1:9117/cron/cloudflare/Warmup 300

# Warmup перед запуском rutracker-parse
55 * * * *       /opt/jacred/Data/run-job.sh cloudflare-warmup http://127.0.0.1:9117/cron/cloudflare/Warmup 300

# Парсинг Rutracker каждый час
0 * * * *        /opt/jacred/Data/run-job.sh rutracker-parse http://127.0.0.1:9117/cron/rutracker/parse 3600
```

<Warning>
  Без прогрева сессии первый запрос к rutracker после простоя займёт ~80 секунд вместо 2-3. Warmup открывает сессию `jacred-rutracker_org`; kinozal.guru при этом не прогревается.
</Warning>
