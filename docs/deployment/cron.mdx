JacRed не запускает парсеры самостоятельно. Системный cron вызывает HTTP-эндпоинты через `Data/run-job.sh`. Источник истины для минут и часов — файл `Data/crontab` в репозитории. На страницах [трекеров](/trackers/overview) те же команды по одному slug.

```text
crontab → run-job.sh → curl GET → /cron/{slug}/{action}
```

`run-job.sh` берёт `flock` по имени задачи: если предыдущий curl ещё не вернулся, новый пропускается. Для `ParseAllTask` и `UpdateTasksParse` HTTP сразу отвечает `ok` и работа идёт в фоне — `max_time=60` у runner это только ack, не длина обхода.

## Типы задач

| Тип | Эндпоинт | Зачем | Kick | Пока уже идёт |
| --- | --- | --- | --- | --- |
| `parse` | `GET /cron/{slug}/parse` | Свежие раздачи (обычно первые страницы) | Часто: 15 мин, 20 мин или раз в час | `flock` / parse-lock, повтор пропускается |
| `UpdateTasksParse` | `GET /cron/{slug}/UpdateTasksParse` | Пересчитать карту страниц в `Data/temp/{slug}_taskParse.json` | Раз в сутки ночью (02:xx–03:20) | Exclusive с ParseAll и ParseLatest |
| `ParseAllTask` | `GET /cron/{slug}/ParseAllTask` | Полный обход текущей карты | См. [таблицу ParseAll](#parsealltask) | Ответ `work`; новый круг только при pending = 0 |
| `ParseLatest` | `GET /cron/{slug}/ParseLatest` | Первые страницы каждой категории | Раз в сутки утром (07:xx) | Exclusive с ParseAll и UpdateTasks |
| `backfill` | `GET /cron/{slug}/backfill` | Архив API по checkpoint | Каждый час | Состояние на диске (`Data/temp/`) |
| `ParseShows` | `GET /cron/subsplease/ParseShows` | Сезон-паки SubsPlease | Раз в сутки 05:25 | — |
| `ResumeParseAll` | `GET /cron/maintenance/ResumeParseAll` | Продолжить цикл после рестарта | Каждые 15 мин и ~45 с после старта процесса | `work`, если задача жива; `idle`, если pending = 0 |
| `jsondb-save` | `GET /jsondb/save` | Сброс FileDB на диск | Каждые 5 мин | — |
| `cloudflare-warmup` | `GET /cron/cloudflare/Warmup` | Держать `cf_clearance` | Keepalive каждые 20 мин, warmup в :55 перед rutracker-parse | — |
| `maintenance Check` | `GET /cron/maintenance/Check?mode=report` | Отчёт по FileDB | Воскресенье 05:00 | — |

<Note>
  Hourly `parse` не ждёт ParseAll: между страницами архивного обхода ParseAll уступает свежести. Не запускайте вручную `UpdateTasksParse` и `ParseAllTask` одного трекера одновременно.
</Note>

## Служебные задачи

| Имя в crontab | Расписание | `max_time` |
| --- | --- | --- |
| `jsondb-save` | `*/5 * * * *` | 60 с |
| `cloudflare-keepalive` | `5,25,45 * * * *` | 300 с |
| `cloudflare-warmup` | `55 * * * *` | 300 с |
| `parseall-resume` | `*/15 * * * *` | 60 с |
| `maintenance-check` | `0 5 * * 0` | 60 с |

## ParseAllTask

Kick — это не «убить и начать заново». Если цикл ещё идёт, cron получает `work`. Если `pending = 0`, kick начинает **новый** круг. Стены по часам нет: обход идёт до pending = 0, shutdown или 45 мин без прогресса. Частота kick = как часто стартовать новый круг у тех, кто успевает закончить.

| Трекер | Карта | Круг | Kick | Почему так |
| --- | --- | --- | --- | --- |
| [`rutracker`](/trackers/rutracker) | ~16k стр. | сутки+ | `40 4 * * *` | Не учащать: цикл и FlareSolverr и так непрерывные |
| [`ultradox`](/trackers/ultradox) | ~3.6k | ~9 ч | `58 12 * * *` | После утренней волны, один круг до UpdateTasks |
| [`nnmclub`](/trackers/nnmclub) | ~5k | ~7 ч | `42 12 * * *` | Как ultradox, не вместе с 05:xx |
| [`kinozal`](/trackers/kinozal) | ~6k | ~4 ч | `35 5,17 * * *` | Два круга; третий наложится на FlareSolverr rutracker |
| [`rutor`](/trackers/rutor) | ~4k | ~3.5 ч | `30 5,17 * * *` | Два круга влезают до ночного UpdateTasks |
| [`korsars`](/trackers/korsars) | ~1.7k | ~3.6 ч | `53 5,17 * * *` | Как rutor |
| [`anibelka`](/trackers/anibelka) | ~154 | ~3.7 ч | `48 5,17 * * *` | Мало страниц, но каждая тянет топик |
| [`megapeer`](/trackers/megapeer) | ~77 | ~1.3 ч | `45 5,13,21 * * *` | `reqMinute: 5`, три круга без наложений |
| [`toloka`](/trackers/toloka) | ~783 | ~1–2 ч | `55 5,13,21 * * *` | Средняя карта, те же окна что megapeer |
| [`torrentby`](/trackers/torrentby) | ~197 | минуты | `50 5,11,17,23 * * *` | Самый короткий trio-цикл, каждые 6 ч |

## Установка crontab

```bash
crontab /opt/jacred/Data/crontab
crontab -l
```

## run-job.sh

Три аргумента: имя задачи, URL, `max_time` в секундах.

```bash
/opt/jacred/Data/run-job.sh kinozal-parse http://127.0.0.1:9117/cron/kinozal/parse 900
```

Если запрос идёт не из LAN, добавьте `devkey`:

```bash
http://127.0.0.1:9117/cron/kinozal/parse?devkey=YOUR_DEV_KEY
```

Эндпоинты `/cron/*` требуют прямого LAN-доступа или `devkey`. Через reverse proxy ключ нужен и в локальной сети. Подробнее: [аутентификация](/authentication) и [Cron API](/api-reference/cron).

<Warning>
  Не запускайте два `ParseAllTask` одного трекера одновременно. Это приведёт к конкурентной записи в FileDB.
</Warning>
