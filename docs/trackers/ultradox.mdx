Ultradox, slug `ultradox`, работает без авторизации. Использует Rutor-стиль trio плюс `ParseLatest`. Канонический хост — `https://ultradox.vip` (307 на номерное зеркало `00N.ultradox.vip`). URL в FileDB остаются на `ultradox.vip`, не на зеркале. Сайт может вернуть 503, если запрос приходит с Referer собственного домена; JacRed подставляет Referer, похожий на страницу поиска Google или Yandex.

<Warning>
  Не переопределяйте заголовок `Referer` в прокси или CDN на пути от JacRed к `ultradox.vip`. Собственный Referer вызовет ответ 503. После `MarkGuarded` страница идёт через cffetch / FlareSolverr — JacRed прокидывает туда тот же поисковый Referer. Без него listing пустой (`fetched=0`, `Listing fetch failed`), а пустой ответ раньше помечал страницу ParseAll как выполненную.
</Warning>

<Note>
  Не задавайте `alias` на конкретное `002.ultradox.vip` — номерное зеркало меняется. `HttpClient` следует за 307.
</Note>

## Конфигурация

```yaml
Ultradox:
  host: https://ultradox.vip
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
```

Runtime читает `./init.yaml` из CWD, не шаблон `Data/init.yaml`. После смены хоста на уже заполненной базе: бэкап `Data/fdb/`, затем `GET /dev/FixUltradoxDomainDuplicates` — переписывает `ultradox.onl` и `00N.ultradox.vip` на канонический хост и сливает дубли по `path+#h=`.

## Расписание cron

```crontab
# Основной parse каждые 30 минут
13,43 * * * *  /opt/jacred/Data/run-job.sh ultradox-parse http://127.0.0.1:9117/cron/ultradox/parse 900

# Обновление очереди
50 2 * * *  /opt/jacred/Data/run-job.sh ultradox-UpdateTasksParse http://127.0.0.1:9117/cron/ultradox/UpdateTasksParse 60

# Полный перебор раз в сутки после утренней волны (~9 ч)
58 12 * * *  /opt/jacred/Data/run-job.sh ultradox-ParseAllTask http://127.0.0.1:9117/cron/ultradox/ParseAllTask 60

# Свежие релизы раз в сутки
20 7 * * *  /opt/jacred/Data/run-job.sh ultradox-ParseLatest http://127.0.0.1:9117/cron/ultradox/ParseLatest 900
```

<Note>
  После рестарта незавершённый цикл продолжает `GET /cron/maintenance/ResumeParseAll` (~45 с после старта и cron `*/15`). Cron `ParseAllTask` начинает новый круг только когда pending = 0.
</Note>

<Note>
  `UpdateTasksParse` берёт **меньшую** последнюю страницу среди пейджеров раздела: футер на DLE завышен (пустые страницы), ajax-виджет завышает в другую сторону. Числа из `<script>` не считаются. Слоты за живым хвостом удаляются. Пустой HTML карту не обнуляет.
</Note>
