Ultradox, slug `ultradox`, работает без авторизации. Использует Rutor-стиль trio плюс `ParseLatest`. Сайт возвращает 503, если запрос приходит с Referer собственного домена; JacRed автоматически подставляет Referer, похожий на страницу поиска Google или Yandex.

<Warning>
  Не переопределяйте заголовок `Referer` в прокси или CDN на пути от JacRed к `ultradox.onl`. Собственный Referer вызовет ответ 503. После `MarkGuarded` страница идёт через cffetch / FlareSolverr — JacRed прокидывает туда тот же поисковый Referer. Без него listing пустой (`fetched=0`, `Listing fetch failed`), а пустой ответ раньше помечал страницу ParseAll как выполненную.
</Warning>

## Конфигурация

```yaml
Ultradox:
  host: https://ultradox.onl
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
```

## Расписание cron

```crontab
# Основной parse каждые 30 минут
13,43 * * * *  /opt/jacred/Data/run-job.sh ultradox-parse http://127.0.0.1:9117/cron/ultradox/parse 900

# Обновление очереди
50 2 * * *  /opt/jacred/Data/run-job.sh ultradox-UpdateTasksParse http://127.0.0.1:9117/cron/ultradox/UpdateTasksParse 60

# Полный перебор раз в сутки после утренней волны (~9 ч)
58 12 * * *  /opt/jacred/Data/run-job.sh ultradox-ParseAllTask http://127.0.0.1:9117/cron/ultradox/ParseAllTask 60

# Свежие релизы раз в сутки
20 7 * * *  /opt/jacred/Data/run-job.sh ultradox-ParseLatest http://127.0.0.1:9117/cron/ultradox/ParseLatest 900
```

<Note>
  После рестарта незавершённый цикл продолжает `GET /cron/maintenance/ResumeParseAll` (~45 с после старта и cron `*/15`). Cron `ParseAllTask` начинает новый круг только когда pending = 0.
</Note>

<Note>
  `UpdateTasksParse` читает футер-пейджер раздела (не ajax-виджет и не числа из `<script>`) и удаляет слоты за последней страницей. Пустой HTML карту не обнуляет.
</Note>

## Диагностика

curl "http://localhost:9117/cron/ultradox/parse"
