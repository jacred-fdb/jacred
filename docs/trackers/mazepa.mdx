Mazepa, slug `mazepa`, содержит около 51 тысячи раздач. Украинский трекер, требует авторизации. Специальный полный обход форумов: только задача `parse`, без trio-кластера. Магнет-ссылки собираются из `.torrent` без announce (`MagnetNoTrackers`), чтобы passkey сессии не попал в FileDB. Клиент ищет пиров через DHT.

## Конфигурация

<CodeGroup>
```yaml Cookie
Mazepa:
  host: https://mazepa.to
  alias: ""
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
  cookie: "bb_data=SESSION"
```

```yaml Логин/пароль
Mazepa:
  host: https://mazepa.to
  alias: ""
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
  login:
    u: "mylogin"
    p: "mypassword"
```
</CodeGroup>

- `host` задаёт основной адрес.
- `alias` заменяет адрес запросов.
- `useproxy` применяет глобальный прокси.
- Предпочитайте статическую `cookie`, если сессия уже есть.

Не коммитьте живые cookie и пароли в git.

## Действия парсера

| Путь | Назначение |
| --- | --- |
| `/cron/mazepa/Parse` | Полный обход форумов Mazepa |

## Расписание

Стандартный `Data/crontab` использует:

```crontab
25 */2 * * *  /opt/jacred/Data/run-job.sh mazepa-parse http://127.0.0.1:9117/cron/mazepa/parse 2400
```

`parse` обходит все форумы (~27 мин). `max_time` 2400 с, чтобы curl не оборвал прогон. Kick каждые 2 часа.

## Диагностика

```bash
curl http://127.0.0.1:9117/cron/mazepa/parse
curl http://127.0.0.1:9117/health/background-jobs
tail -f /opt/jacred/Data/log/mazepa.log
```

Если запросы не проходят, проверьте `host`, cookie/login и [настройку прокси](/configuration/proxy). Если endpoint возвращает `401` или `403`, проверьте [матрицу доступа](/operations/access-matrix).
