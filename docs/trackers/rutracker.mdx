Rutracker — крупнейший трекер в базе JacRed (~1.5 миллиона раздач). Он защищён Cloudflare, что требует специальной настройки через FlareSolverr.

## Требования

- FlareSolverr для обхода Cloudflare challenge
- cffetch (`ghcr.io/jacred-fdb/cffetch`, `:8192`) — быстрые GET после solve; без него остаётся браузер
- На VPS с датацентровым IP: WARP + FlareSolverr, тот же SOCKS у cffetch

## Конфигурация

```yaml
flaresolverr:
  enable: true
  url: http://host.docker.internal:8191/v1   # JacRed на bridge, FS host network
  crawlUrl: http://host.docker.internal:8193/v1  # ParseAll / UpdateTasks; пусто — тот же url
  maxTimeoutMs: 300000
  sessionIdleMinutes: 120
  browserTimeoutRetries: 1
  recycleAfterTimeouts: 3
  guardedHours: 6
  recheckMinutes: 30

cffetch:
  enable: true
  url: http://host.docker.internal:8192/fetch
  impersonate: chrome136
  proxy: socks5://127.0.0.1:20001

Rutracker:
  host: https://rutracker.org
  alias: ""              # Worker URL если flaresolverr.enable=false
  useproxy: false
  reqMinute: 30          # 60 отзывает cf_clearance; 8 слишком медленно для 16k страниц
  topicFetchAttempts: 5  # повторов на получение магнета
  log: true
```

## Расписание cron

```crontab
# Прогрев каждые 20 минут
5,25,45 * * * *  /opt/jacred/Data/run-job.sh cloudflare-keepalive http://127.0.0.1:9117/cron/cloudflare/Warmup 300

# Warmup перед parse
55 * * * *  /opt/jacred/Data/run-job.sh cloudflare-warmup http://127.0.0.1:9117/cron/cloudflare/Warmup 300

# Парсинг каждый час
0 * * * *   /opt/jacred/Data/run-job.sh rutracker-parse http://127.0.0.1:9117/cron/rutracker/parse 3600

# Обновление очереди
20 3 * * *  /opt/jacred/Data/run-job.sh rutracker-UpdateTasksParse http://127.0.0.1:9117/cron/rutracker/UpdateTasksParse 60

# Полный перебор — утром новый цикл, если предыдущий закончен
40 4 * * *  /opt/jacred/Data/run-job.sh rutracker-ParseAllTask http://127.0.0.1:9117/cron/rutracker/ParseAllTask 60

# После рестарта / зависания — продолжить pending (не начинает новый круг)
*/15 * * * *  /opt/jacred/Data/run-job.sh parseall-resume http://127.0.0.1:9117/cron/maintenance/ResumeParseAll 60
```

Hourly `parse` — источник свежести. `ParseAllTask` обходит карту форумов (~13–16k страниц): одна GET листинга на страницу, `sid`/`pir` мержатся в FileDB. Topic GET (магнит) только если title сменился. Пустой magnet с форума не затирает сохранённый. Цикл живёт в `Data/temp/rutracker_parseAllCycle.json`. Стены по часам нет: обход идёт до pending=0, shutdown или 45 мин без прогресса. После обслуживания: `curl /cron/maintenance/ParseAllStatus` и `ResumeParseAll` (ещё срабатывает сам через ~45 с после старта процесса).

## Принцип работы с Cloudflare

```text
JacRed → FlareSolverr → Chromium → rutracker.org (CF challenge ~11s)
                      → кеш сессии (~0.5s при активном Chromium)
```

`cf_clearance` хранится в браузерной сессии FlareSolverr (`jacred-rutracker_org`). Hourly parse ходит на `flaresolverr.url`. ParseAll / UpdateTasks / ParseLatest — на `crawlUrl` (второй экземпляр), иначе живой браузер съедает архивный обход. Несколько сессий в одном FlareSolverr почти не ускоряют.

## Режим без FlareSolverr

Если FlareSolverr недоступен, установите `alias` — Worker URL для проксирования запросов:

```yaml
Rutracker:
  host: https://rutracker.org
  alias: "https://your-worker.example.com"

flaresolverr:
  enable: false
```

<Warning>
  Без FlareSolverr или alias JacRed получит 403 от Cloudflare при каждом запросе к rutracker.org.
</Warning>

## Диагностика

```bash
# Проверить статус FlareSolverr-сессии
curl "http://localhost:9117/cron/cloudflare/Warmup"

# Запустить парсинг вручную
curl "http://localhost:9117/cron/rutracker/parse"

# Проверить фоновые задачи
curl "http://localhost:9117/health/background-jobs"

# Статус циклов ParseAll (pending / running)
curl "http://localhost:9117/cron/maintenance/ParseAllStatus"

# Продолжить незавершённый цикл после рестарта
curl "http://localhost:9117/cron/maintenance/ResumeParseAll"
```
