Anibelka, slug `anibelka`, работает **только анонимно**. Пароли встроены прямо в торрент-файлы, поэтому передавать passkey в магнет-ссылки нельзя. Не задавайте `cookie`, `login.u`, `login.p`. Использует Rutor-стиль trio + дополнительная задача `ParseLatest`.

<Warning>
  **Не заполняйте `cookie` или `login` для Anibelka.** Passkey из аккаунта попадёт в магнет-ссылку и станет публичным при передаче через API JacRed.
</Warning>

## Конфигурация

```yaml
Anibelka:
  host: https://anibelka.com
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
  # cookie и login должны оставаться пустыми
```

## Расписание cron

```crontab
# Основной parse каждые 30 минут
29,59 * * * *  /opt/jacred/Data/run-job.sh anibelka-parse http://127.0.0.1:9117/cron/anibelka/parse 900

# Обновление очереди
40 2 * * *  /opt/jacred/Data/run-job.sh anibelka-UpdateTasksParse http://127.0.0.1:9117/cron/anibelka/UpdateTasksParse 60

# Полный перебор дважды в сутки (~3.7 ч)
48 5,17 * * *  /opt/jacred/Data/run-job.sh anibelka-ParseAllTask http://127.0.0.1:9117/cron/anibelka/ParseAllTask 60

# Свежие релизы раз в сутки
10 7 * * *  /opt/jacred/Data/run-job.sh anibelka-ParseLatest http://127.0.0.1:9117/cron/anibelka/ParseLatest 900
```

<Note>
  После рестарта незавершённый цикл продолжает `GET /cron/maintenance/ResumeParseAll` (~45 с после старта и cron `*/15`). Cron `ParseAllTask` начинает новый круг только когда pending = 0.
</Note>

<Note>
  `UpdateTasksParse` берёт последнюю страницу из живого пейджера форума (числа из `<script>` не считаются) и удаляет слоты за этим хвостом. Пустой HTML карту не обнуляет.
</Note>

## Диагностика

```bash
curl "http://localhost:9117/cron/anibelka/parse"
curl "http://localhost:9117/cron/anibelka/ParseLatest"
tail -f /opt/jacred/Data/log/anibelka.log
```
