Korsars, slug `korsars`, требует авторизации через cookie `bb_data` или логин/пароль. Использует Rutor-стиль trio плюс дополнительную задачу `ParseLatest`. Поддерживает `alias` для смены зеркала: FDB-ссылки остаются на `host`, HTTP-запросы идут через `rqHost`.

## Конфигурация

<CodeGroup>

```yaml Cookie
Korsars:
  host: https://korsars.pro
  alias: ""
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
  cookie: "bb_data=1-USER_ID-HASH-IP-UA_HASH"
```

```yaml Логин/пароль
Korsars:
  host: https://korsars.pro
  alias: ""
  useproxy: false
  reqMinute: 8
  parseDelay: 7000
  log: true
  login:
    u: "mylogin"
    p: "mypassword"
```

</CodeGroup>

### Формат cookie

Значение `bb_data` состоит из пяти сегментов, разделённых дефисами: `1-USER_ID-HASH-IP-UA_HASH`. Получите его из DevTools: Application → Cookies → korsars.pro.

## Расписание cron

```crontab
# Основной parse
15,27,45,57 * * * *  /opt/jacred/Data/run-job.sh korsars-parse http://127.0.0.1:9117/cron/korsars/parse 900

# Обновление очереди
45 2 * * *  /opt/jacred/Data/run-job.sh korsars-UpdateTasksParse http://127.0.0.1:9117/cron/korsars/UpdateTasksParse 60

# Полный перебор дважды в сутки (~3.6 ч)
53 5,17 * * *  /opt/jacred/Data/run-job.sh korsars-ParseAllTask http://127.0.0.1:9117/cron/korsars/ParseAllTask 60

# Свежие релизы раз в сутки
15 7 * * *  /opt/jacred/Data/run-job.sh korsars-ParseLatest http://127.0.0.1:9117/cron/korsars/ParseLatest 900
```

<Note>
  После рестарта незавершённый цикл продолжает `GET /cron/maintenance/ResumeParseAll` (~45 с после старта и cron `*/15`). Cron `ParseAllTask` начинает новый круг только когда pending = 0.
</Note>

<Note>
  `UpdateTasksParse` берёт последнюю страницу из живого пейджера и удаляет слоты за этим хвостом. Пустой HTML карту не обнуляет.
</Note>

## Диагностика

```bash
curl "http://localhost:9117/cron/korsars/parse"

tail -f /opt/jacred/Data/log/korsars.log
```
