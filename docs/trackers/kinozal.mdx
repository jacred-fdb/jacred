Kinozal — один из крупнейших трекеров в базе JacRed (~550 тысяч раздач). Требует авторизации через cookie или логин/пароль. Использует кодировку cp1251, которую JacRed конвертирует автоматически.

## Конфигурация

<CodeGroup>

```yaml Cookie (предпочтительно)
Kinozal:
  host: https://kinozal.guru
  useproxy: false
  reqMinute: 4
  parseDelay: 10000
  log: true
  cookie: "uid=USER_ID; pass=PASS_HASH"
```

```yaml Логин/пароль
Kinozal:
  host: https://kinozal.guru
  useproxy: false
  reqMinute: 4
  parseDelay: 10000
  log: true
  login:
    u: "mylogin"
    p: "mypassword"
```

</CodeGroup>

### Как получить cookie

1. Войдите в аккаунт на текущем домене Kinozal.
2. Откройте DevTools (F12) → Application → Cookies.
3. Скопируйте значения `uid` и `pass`.
4. Вставьте в формате `uid=ЗНАЧЕНИЕ; pass=ЗНАЧЕНИЕ`.

<Warning>
  Cookie протухает при явном выходе из аккаунта или смене пароля. При пустых результатах парсинга проверьте актуальность cookie.
</Warning>

## Cloudflare

`kinozal.guru` отдаёт `403` с `cf-mitigated: challenge`. Прямой HTTP из JacRed не проходит. Списки (`browse.php`) и info-hash (`get_srv_details.php`) после solve идут через **cffetch** (`ghcr.io/jacred-fdb/cffetch`, TLS Chrome); браузер FlareSolverr — первая страница и fallback. У Kinozal своя сессия Chromium (`jacred-kinozal_guru`). Замер master 10.09.2026: hash GET ~0.18 с и без stale-вкладки, тогда как `request.get` иногда возвращал предыдущий browse.

FlareSolverr/Chromium отдаёт листинг с двойными кавычками у атрибутов (`class="first bg"`, `class="s"`). Парсер принимает и этот HTML, и старый wire-формат (`class='first bg'`, `class=bg`). URL в FileDB — только `/details.php?id=…` (раздача), не `/userdetails.php?id=` (профиль раздающего).

Пустая «залогиненная» оболочка без таблицы `t_peer` (~15 KB, есть `Выход`) бывает двух видов:

- **Stale-вкладка FlareSolverr** — нет фразы «Нет активных раздач». JacRed ретраит до четырёх GET с паузой 3 с, после серии stale пересоздаёт сессию хоста и **не** помечает страницу ParseAllTask как выполненную.
- **Пустая выдача года** — тот же размер, но в HTML «Нет активных раздач». Это реальный ответ поиска (хвост `page=N` за последней страницей листинга). ParseAll помечает страницу done (`browse empty search`), recycle не нужен, **только если** в форме выбранные `c` и `d` совпадают с URL. Чужой HTML (другая категория/год в `<select>`) — leftover-вкладка FlareSolverr: `browse filter mismatch`, ретрай как stale, страницу **не** помечают done. Для `page=0` JacRed делает ещё два GET — пустой документ может быть предыдущей вкладкой. Фраза «уточните параметры поиска» есть и на листингах с >5000 раздач — её одной недостаточно.

Цифра в пейджере сразу перед `rel="next"` — 1-based номер последней страницы с раздачами. URL `page` 0-based: при цифре `15` в очередь идут `0..14`, а не `0..15`. Старый цикл `page <= digit` как у NNMClub здесь как раз добавлял пустой хвост. `UpdateTasksParse` при пересчёте **удаляет** уже записанные хвосты (`page >= count`), иначе каждый цикл ParseAll снова ходит на «Нет активных раздач».

Короткая ссылка джобов (`c=&page=&d=&t=1`) совпадает с пейджером сайта; полная форма `s=&g=0&v=0&w=0&f=0` не нужна. `t=1` — сортировка «Сидам», не фильтр «активные». Hourly `parse` без года: `c=&page=0`.

Hourly `parse` не блокируется фоновым ParseAll: свежие раздачи (`/browse.php?c=&page=0`) идут каждые 15 минут, а архивный обход по годам уступает между страницами. `UpdateTasksParse`, `ParseAllTask` и `ParseLatest` по-прежнему взаимоисключающие. Не запускайте UpdateTasks и ParseAll вручную одновременно. В `/health/background-jobs` `percent` у ParseAll — это обойдённые страницы очереди, не число новых магнитов в FileDB; в `kinozal.log` смотрите `ParseAllTask ok=успех/попытки`.

Нужны cookie (или login) и `flaresolverr.enable: true`. Подробнее: [FlareSolverr](/configuration/flaresolverr).

## Расписание cron

```crontab
# Парсинг каждые 15 минут
3,18,33,48 * * * *  /opt/jacred/Data/run-job.sh kinozal-parse http://127.0.0.1:9117/cron/kinozal/parse 900

# Обновление очереди
10 2 * * *  /opt/jacred/Data/run-job.sh kinozal-UpdateTasksParse http://127.0.0.1:9117/cron/kinozal/UpdateTasksParse 60

# Полный перебор дважды в сутки (~4 ч)
35 5,17 * * *  /opt/jacred/Data/run-job.sh kinozal-ParseAllTask http://127.0.0.1:9117/cron/kinozal/ParseAllTask 60
```

<Note>
  После рестарта незавершённый цикл продолжает `GET /cron/maintenance/ResumeParseAll` (~45 с после старта и cron `*/15`). Cron `ParseAllTask` начинает новый круг только когда pending = 0.
</Note>

## Домен и зеркала

В релизе 3.9.3 домен по умолчанию — `kinozal.guru`. Обновляйте `host`, если рабочее зеркало изменилось.

<Note>
Магниты берутся из `get_srv_details.php` (hash-to-magnet), а не из списка. Запрос — GET через FlareSolverr, поэтому полный проход медленнее, чем у трекеров с магнитом в листинге.
</Note>

```bash
# Обход Cloudflare: listing + info-hash через FlareSolverr
python3 scripts/flaresolverr_kinozal_cf_check.py

# Хвосты года (~15269 байт) vs parsePage: empty search → done, stale → retry
python3 scripts/kinozal_empty_tail_check.py

# Ручной запуск парсинга
curl "http://localhost:9117/cron/kinozal/parse"

# Проверить логи
tail -f /opt/jacred/Data/log/kinozal.log
```
